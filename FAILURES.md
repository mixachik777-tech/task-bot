# FAILURES — task-bot

Журнал классов повторяющихся ошибок этого проекта. **Soft-режим по умолчанию:** содержимое этого файла инжектится в активный контекст Claude в начале каждой сессии работы в данном проекте через `kb-sessionstart`-механику. То есть Claude **видит список классов до начала работы** — это превентивная видимость, а не реактивная блокировка.

Жёсткая regex-блокировка ответа через Stop-хук применяется **только** к классам с явной пометкой `Mode: hard` — это редкое и осознанное исключение для случаев где «лучше ложное срабатывание, чем пропуск».

## Формат блока

```markdown
## YYYY-MM-DD — class-name (kebab-case)

**Class**: одно предложение про класс ошибки (не про инцидент!).

**Mode**: soft
<!-- "soft" — только инжект в контекст для самоконтроля (дефолт).
     "hard" — Stop-хук блокирует ответ при regex-match.
     Hard ставить только когда: ложное срабатывание дешевле пропуска
     (необратимые операции, утечка секретов, обращение к прод-сервисам). -->

**Triggers**: (для soft — необязательно; для hard — обязательно)
regex1|regex2|regex3

**Rule**: feedback_<name>.md (если правило сформулировано)
<!-- Или "(сырое — отправлено в Discover memory-hygiene)" если правило
     ещё не прошло через quality gate skill'а. -->

**Контекст инцидента:** что произошло, ссылка на коммит/PR/transcript.

**Корневая причина:** одной строкой.

**Фикс:** что сделано чтобы класс не повторился.
```

## Принципы записи

1. **Класс, не инцидент.** Antipattern: «не путать ключ DaData с ключом Yandex.Maps». Правильно: «При нескольких внешних API всегда проверять какой ключ для какого сервиса».
2. **Soft — дефолт.** Перед пометкой `hard` спроси себя: «слово/фраза-триггер может сработать в нормальном контексте?» Если да — оставь soft.
3. **Корпус правил формируется не вручную.** Свежие классы попадают сюда как сырой ввод. Их обработка через `memory-hygiene` skill (quality gate, dedup, tier classification, promotion). Не дописывать правило в `feedback_*.md` вручную минуя skill.
4. **Не плодить дубли.** Перед добавлением блока — `grep` по существующим Class-формулировкам в этом файле. Если близкий класс есть — расширь его.

## Скиллы-помощники

- `memory-hygiene` — Discover/Report по корпусу правил, quality gate для нового класса, классификация incorporated/pending/dormant/superseded
- `postmortem-writing` — 5-whys / blameless timeline для содержательной формулировки Class и Корневой причины
