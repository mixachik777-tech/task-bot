# task-bot

Telegram-бот для управления задачами редакции с AI-ассистентом на Gemini 2.5 Flash.

Что умеет:

- Постановка задач в супергруппе с форум-топиками (по одному топику на отдел + закрытый «Руководство»).
- Полный жизненный цикл задачи: принять → завершить → отменить → комментарии.
- Архив со фильтрами (отдел / исполнитель / период / статус) и пагинацией.
- Состав сотрудников с распределением по отделам — только Telegram-админам.
- Статистика и продуктивность каждого сотрудника с PNG-графиками динамики.
- AI-помощник на естественном языке: «мои просрочки», «найди задачи про обложку», «что у Алёны в работе», «сформулируй задачу: афиша 9 мая».
- Напоминания о приближающихся дедлайнах (за 2 дня / 1 день / 2 часа) и уведомления о просрочках со ссылкой на сообщение.
- Поддержка вложений: документы любых форматов (.pdf .doc .xls .ai .pptx .svg .ttf и т.п.), фото, видео .mp4, GIF.

## Развёртывание на новом VPS

Требования к серверу:

- Linux x86-64 (Ubuntu 22.04+, Debian 11+, AlmaLinux 9+ — любой современный).
- 2 ГБ RAM (минимум, при активной работе на 10+ сотрудниках — лучше 4 ГБ).
- 10 ГБ места на диске для образов + данных БД и бэкапов.
- Docker Engine 24+ и Docker Compose v2.
- Открытый исходящий доступ к `api.telegram.org` и `generativelanguage.googleapis.com`.

### Шаг 1. Получить токены

#### 1.1 Telegram Bot

1. Открой `@BotFather` в Telegram.
2. `/newbot` → имя (любое) → username (должен оканчиваться на `bot`, например `clientname_tasks_bot`).
3. BotFather пришлёт `BOT_TOKEN` вида `8169861731:AAG…`. Это секрет — сохрани.
4. Для бота выключи приватный режим (чтобы он видел сообщения в группах): `/setprivacy` → выбери бота → `Disable`.

#### 1.2 Свой Telegram-id

1. Открой `@userinfobot`, отправь любое сообщение — он пришлёт твой численный `user_id`.
2. Это значение `ADMIN_TG_ID` — пользователь, который при первом старте бота сразу становится админом.

#### 1.3 Google AI Studio (Gemini)

1. Зайди на https://aistudio.google.com/app/apikey под Google-аккаунтом.
2. «Create API key» → выбери или создай project → скопируй ключ вида `AIzaSy…`.
3. Бесплатный tier: 10 RPM / 250 запросов в день / 250k токенов в минуту на ВЕСЬ ключ. На редакцию из 5-10 человек этого хватает с запасом.
4. Если AI не нужен — это поле можно оставить пустым, остальной функционал работает.

### Шаг 2. Настроить Telegram-супергруппу

1. Создай новую группу в Telegram (название любое: «Редакция»).
2. Преобразуй в супергруппу: настройки группы → «Тип группы» → «Публичная/Приватная» (любое).
3. **Включи форум-топики**: настройки группы → «Темы» → активируй.
4. **Создай 4 топика** (4 кнопки «+» сверху или через настройки): «Корректоры», «Дизайнеры», «Корреспонденты», «Руководство».
5. **Закрой топик «Руководство»**: тап-удержание на топик → «Закрыть тему». Теперь в нём смогут писать только админы группы (бот тоже).
6. **Добавь бота админом** в группу с правами: `Manage topics`, `Delete messages`, `Pin messages`. Без них не сможет постить карточки и редактировать их.
7. **Запиши topic_id каждого топика**: проще всего так — добавь бота и любым сообщением подними его в топик; бот при первом `/set_topic` (см. ниже) сам узнает текущий topic_id из контекста сообщения.

### Шаг 3. Скопировать код и заполнить .env

```bash
# на VPS
git clone <url-репозитория> /opt/task-bot
cd /opt/task-bot

cp .env.example .env
nano .env
```

Заполни поля:

- `BOT_TOKEN` — из шага 1.1
- `ADMIN_TG_ID` — из шага 1.2
- `DB_PASSWORD` — любая случайная строка: `openssl rand -hex 16`
- `GEMINI_API_KEY` — из шага 1.3 (можно пустым)
- `AI_USER_DAILY_LIMIT` — дневной лимит вопросов AI на пользователя (по умолчанию 30)
- `TASK_CHAT_ID`, `LEADERSHIP_TOPIC_ID` — оставь пустыми, заполним позже через команды бота

Запусти preflight-проверку:

```bash
make preflight
```

Скрипт проверит Docker, .env и доступные порты.

### Шаг 4. Запуск

```bash
make up        # docker compose up -d --build
make logs      # живой лог; должно появиться «Старт task-bot» + «Запуск polling»
```

Если на пятой секунде бот не разлогировал «Запуск polling» — открой `docker compose logs bot | tail -50` и смотри ошибку.

### Шаг 5. Привязать бота к группе

В **личке** боту:

```
/start
```

Бот ответит «Здравствуйте» с главным меню. Если получил «ожидает одобрения» — значит ADMIN_TG_ID в .env не совпадает с твоим Telegram-id; поправь .env, `make restart`.

В **общем чате** (не в топике):

```
/set_chat
```

Бот запишет chat_id супергруппы в свою БД.

В **каждом топике отдела** (Корректоры, Дизайнеры, Корреспонденты):

```
/set_topic
```

Бот привязывает текущий топик к отделу. Используй автодиалог: бот спросит, к какому отделу относится топик, ты выберешь кнопкой.

В **топике «Руководство»**:

```
/set_leadership_topic
```

После этого карточки задач будут зеркалиться в этот топик (закрытый, видимый только тем, кому открыт доступ).

### Шаг 6. Добавить сотрудников

Каждый новый сотрудник пишет боту в личке `/start`. Бот скажет «ожидает одобрения».

Админ из своей личке отвечает:

```
/approve <их_tg_id> <код_отдела> <роль>
```

- `<код_отдела>`: `correctors`, `designers`, `correspondents` или `-` (без отдела)
- `<роль>`: `employee`, `lead`, `admin`

Узнать `tg_id` нового юзера: в логах бота появится строка `AuthMiddleware ... tg_user_id=<id>` после его `/start`.

Альтернативно (Telegram-админы группы): открой «👥 Состав» в личке бота → тапни на сотрудника → выбери отдел.

## Команды админа (полный список)

| Команда | Где | Что делает |
|---|---|---|
| `/start` | личка | первое приветствие / главное меню |
| `/approve <tg_id> <dept> <role>` | личка | активировать нового сотрудника |
| `/set_chat` | супергруппа (не топик) | привязать chat_id к боту |
| `/set_topic` | топик отдела | привязать топик к отделу |
| `/set_leadership_topic` | топик «Руководство» | привязать зеркальный топик |
| `/lead_list` | личка | список Telegram-админов с правом писать в «Руководство» |
| `/cancel` | любой | отменить FSM создания задачи |

## Бэкапы

Создание разового бэкапа:

```bash
make backup
```

Файл `backups/taskbot-YYYY-MM-DD-HHMM.sql.gz` остаётся на диске. Ротация: 14 последних ежедневных + 4 еженедельных воскресных.

Автоматический ежедневный бэкап (cron):

```bash
crontab -e
# добавь строку:
0 3 * * * cd /opt/task-bot && ./scripts/backup.sh >> ./backups/backup.log 2>&1
```

Восстановление:

```bash
make restore F=./backups/taskbot-2026-05-18-0300.sql.gz
make restart
```

## Лимиты и тарифы

- **AI**: free-tier Google AI Studio даёт 10 RPM, 250 запросов/сутки, 250k токенов/мин на весь ключ. На редакцию 5–10 человек хватает с запасом. Если кончится → платный tier через Google Cloud (cards required), 1000 RPM, ~$0.075 за 1M input-токенов.
- **Telegram Bot API файлы**: бот может скачивать файлы до 20 МБ. Большие файлы — приложить ссылку на облако в описании.
- **PostgreSQL**: размер БД на редакцию ~50 МБ за год при 200 задач/мес. Бэкап-архивы сжимаются раз в 10.

## Безопасность

- `.env` в `.gitignore`, **никогда не коммитить**.
- PostgreSQL и Redis биндятся на `127.0.0.1` (5432/6379) — снаружи VPS не доступны.
- Для внешнего psql-доступа — SSH-туннель: `ssh -L 5432:127.0.0.1:5432 user@vps`.
- Уведомления о просрочках идут DM только реальным Telegram-админам супергруппы (через `/lead_list`).
- AI-помощник работает только с задачами этого бота, на off-topic запросы отвечает отбивкой.

## Troubleshooting

**Бот не отвечает на `/start`**

```bash
make logs
# смотри последние 50 строк
```

- `TelegramConflictError`: где-то ещё запущен второй экземпляр бота с тем же `BOT_TOKEN`. Останови.
- `AuthMiddleware failed`: проблема с БД, скорее всего postgres не успел подняться. `make restart`.

**Карточки задач не появляются в топиках**

- Проверь, что выполнены `/set_chat`, `/set_topic` (для каждого отдела), `/set_leadership_topic`. Состояние смотри в `app_settings`:
  ```bash
  make shell-db
  taskbot=# SELECT * FROM app_settings;
  taskbot=# SELECT id, code, name, topic_id FROM departments;
  ```
- Проверь, что бот — администратор группы с правом `Manage topics`.

**AI отвечает «Ассистент временно недоступен»**

- Проверь, что `GEMINI_API_KEY` задан и валиден:
  ```bash
  curl -H "x-goog-api-key: $(grep GEMINI_API_KEY .env | cut -d= -f2)" \
    https://generativelanguage.googleapis.com/v1beta/models | head
  ```
- Если HTTP 200 + список моделей — ключ ОК. Если 400/403 — пересоздай ключ.

**Контейнер `bot` падает в перезапуск**

```bash
docker compose logs bot --tail=100
```

Если повторяющийся stacktrace — `make down && make up`. Если нужен полный сброс БД (потеряются все задачи):

```bash
docker compose down -v   # удаляет volume postgres-data!
make up
```
